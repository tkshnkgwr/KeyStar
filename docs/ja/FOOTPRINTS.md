# KeyStar: リソース消費指標 (FOOTPRINTS)

本書は、名作キーボードランチャー「CraftLaunch 2」の原点思想を受け継ぐ `KeyStar` におけるリソース消費量（RAM、CPU、起動時間、キー入力応答、ホットキー復帰レイテンシ）の実測値および目標指標を定義します。

---

## 1. パフォーマンス目標値 (Target Metrics)

| 指標                         |    目標値    | 目的                                                         |
| :--------------------------- | :----------: | :----------------------------------------------------------- |
| **起動時間 (Cold Start)**    | **< 50 ms**  | アプリケーション起動時の知覚ラグ極小化                       |
| **アイドル時 CPU 使用率**    |   **0.0%**   | バックグラウンド待機時（イベントループ休眠）の完全省電力     |
| **ホットキー復帰レイテンシ** |  **< 1 ms**  | `Alt + Space` 押下からウィンドウ最前面表示・描画までの即応性 |
| **メモリ消費 (常駐時 RAM)**  | **< 15 MB**  | バックグラウンド常駐時の低メモリフットプリント維持           |
| **電卓数式評価時間**         | **< 0.1 ms** | キータイピングごとの `evalexpr` パース・計算のゼロ遅延       |
| **ショートカット走査時間**   |  **< 5 ms**  | 数百件の `.lnk`/`.exe` ディレクトリ再スキャン完了時間        |
| **インクリメンタル補完時間** | **< 0.5 ms** | 入力クエリに対する前方・部分一致スコアリングとソート         |

## 3. メモリ消費プロファイル (Memory Footprint)

```text
+-----------------------------------------------------------+
| KeyStar プロセス空間                                       |
+-----------------------------------------------------------+
| [常駐待機時 (Hidden)]                                      |
| - Winit / Win32 メッセージループ待機 (0.0% CPU)            |
| - ショートカットキャッシュメモリ (数KB〜数十KB)            |
| - RAM 消費量: 約 8〜14 MB (Debug) / 約 4〜8 MB (Release)   |
|                                                            |
| [アクティブ表示時 (Visible / Dropdown 8件)]                |
| - egui / eframe レンダリングパイプライン                   |
| - RAM 消費量: 約 12〜18 MB (Debug) / 約 6〜10 MB (Release) |
+-----------------------------------------------------------+
```

1. **CraftLaunch 3 との決定的な違い**:
   - Python 組み込み型ランチャー（CraftLaunch 3等）では、起動時に Python ランタイムと標準ライブラリ群をロードするため、最小でも 40〜80 MB のメモリを恒常消費します。
   - `KeyStar` は純粋な Rust 単一バイナリであり、ガベージコレクションや外部インタプリタを一切介さないため、常駐時わずか数MBのフットプリントを実現しています。
2. **インデックスメモリの極小化**:
   - メモリ上に保持するのはショートカット名、実体パス、拡張子のみ（1アイテムあたり約 150〜200 バイト）。1,000 件登録しても約 200 KB 未満です。

## 4. 計算量特性 (Algorithmic Complexity)

| 処理フェーズ             |  対象データ規模  |    計算量     | 説明                                                       |
| :----------------------- | :--------------: | :-----------: | :--------------------------------------------------------- |
| **ショートカット走査**   | $N$ 件のファイル |    $O(N)$     | 対象フォルダ内のエントリ一覧をイテレートし拡張子判定       |
| **タイムスタンプ検知**   |  2 監視フォルダ  |    $O(1)$     | フォルダ自体のメタデータ `modified()` 比較のみで走査判定   |
| **インクリメンタル補完** | $N$ 件のアイテム | $O(N \log K)$ | 前方一致・部分一致フィルタ後、上位 $K$ 件（最大8件）を抽出 |
| **電卓数式パース**       |  $M$ 文字の入力  |    $O(M)$     | `evalexpr` による構文木解析・即時評価                      |
| **キーストローク処理**   |    1 イベント    |    $O(1)$     | TextEdit フォーカス維持・先行キー消費・循環選択遷移        |
| **ホットキー押下判定**   |    1 イベント    |    $O(1)$     | ID および `Pressed` 状態の一致比較                         |

## 5. 最適化ロードマップ (Phase 4 計画)

Phase 4 では、以下の最適化コンパイルフラグを `Cargo.toml` に適用し、バイナリサイズとメモリ消費のさらなる極限化を図ります：

```toml
[profile.release]
opt-level = 3
lto = true
codegen-units = 1
panic = "abort"
strip = true
```

- **実行ファイルサイズ目標**: < 5 MB（単一スタンドアロン実行可能ファイル）
- **常駐時メモリ目標**: < 10 MB

## 🎨 UI/UX 改善 & 安定性強化 (2026-11)

- **ネイティブアプリアイコンの導入**:
  - `assets/icon.ico` および `assets/icon.png` を生成し、`build.rs`（`winresource`）による実行ファイルリソース埋め込みとトレイアイコン表示を実装。
- **トレイ設定起動時の異常終了防止**:
  - トレイメニューから「設定」を開く際、メインウィンドウを退避してから設定ダイアログを前面表示するよう制御を改善。
  - ルートウィンドウへの予期せぬクローズ要求に対する `CancelClose` 防御および非表示時の描画バイパスを導入。
- **入力画面の上下センター配置**:
  - 1行入力バー（全高 40px）内でプロンプト記号（`>`）とテキストを垂直中央揃え（`Align::Center`）に配置し、CraftLaunchライクな極小バーの美観を実現。
- **候補ドロップダウンの見切れ解消**:
  - `item_spacing` やセパレータ余白を含めた行高ピッチ（28.0px）と固定追加高さ（18.0px）を再計算し、4行目以降の候補が見切れないよう改善。
- **設定ダイアログの安定性向上**:
  - ウィンドウ初期高さを 560px へ拡大し、最下部のアクションボタン（「保存して適用」等）を固定フッターパネル（`Panel::bottom`）として配置。スクロール時も見切れを完全防止。
