# KeyStar: 開発者・AI指示書 (INSTRUCTIONS)

本書は、`KeyStar` プロジェクトにおける開発者およびAIエージェント向けの行動ガイドライン、アーキテクチャ規約、および作業指示書です。

---

## 1. 最優先遵守ルール (RULES.md 連動)

本ワークスペースにおけるすべての開発作業は、リポジトリ直下の [**`RULES.md`**](../../RULES.md) および [**`GEMINI.md`**](../../GEMINI.md) が最優先の拘束力を持ちます。

1. **自動コミット/Pushの絶対禁止**:
   - ボスからの明示的な指示（「コミットして」「Pushして」等）がない限り、`git commit` や `git push` を自律判断で実行してはならない。
2. **Markdownテーブル垂直整列**:
   - すべてのMarkdown表組みは、全角・半角文字幅を厳格に計算し、パイプ `|` とハイフン `-` を垂直整列させる（gVim等の生テキスト閲覧性を保護）。
3. **呼称および100%日本語化プロトコル**:
   - ボスのことは常に「ボス」とお呼びする。対話、ログ報告、質問、選択肢、解説はすべて100%自然な日本語で行う。
4. **ローカル絶対パスの環境変数化**:
   - ユーザー固有の生パス（`C:\Users\<user>\...`）は使用せず、必ず `%USERPROFILE%`（または `$env:USERPROFILE`）に統一する。
5. **高速CLIツールの標準利用**:
   - ソースコード探索には `rg`、ファイル探索には `fd`、プレビューには `bat --paging=never`、JSON処理には `jq` を最優先で使用する。
6. **コード規模制約 (1000行制限)**:
   - すべての `.rs` ファイルは 1000 行を超えてはならず、肥大化した場合はモジュール分割リファクタリングを義務付ける。

## 2. プロジェクト開発思想 & クリーンルーム方針

- **名作「CraftLaunch 2」の原点復帰**:
  - Python組み込みにより肥大化・複雑化したVer 3ではなく、全ユーザーが熱狂した **Ver 2の原点（1行・爆速・キーボード特化・ショートカット即起動）** をRust (Edition 2024) で再現する。
  - PC全域をインデックス検索する重厚ツールではなく、「自分が決めたフォルダに置いたショートカットだけを最短キーストロークで叩く」という究極のミニマリズムを徹底する。
- **クリーンルーム開発プロトコル**:
  - 本家の内部実装やPython拡張ドキュメントはあえて見ず、**「GUIの見た目（1行の極小テキスト枠、候補リスト）」と「キーボード操作感（ホットキー、インクリメンタル補完、Enter/Esc）」のみ** を踏襲して構築する。

## 3. コミット前必須品質検証手順

ソースコード（`*.rs`）を変更した際は、コミット前に以下の順序で事前検証を行い、全項目PASSを確認すること（`.agents/skills/rust-verification/` 準拠）：

```powershell
# 1. 型チェック & 構文検証
cargo check --all-targets

# 2. 全単体・統合テストの実行
cargo test --all-targets

# 3. ドキュメンテーションテストの実行
cargo test --doc

# 4. 静的解析（警告ゼロ必須）
cargo clippy --all-targets -- -D warnings

# 5. コードフォーマット検証
cargo fmt --check

# 6. コード行数検証（1000行以内）
fd -e rs --exec-batch wc -l
```

## 4. バージョニング ＆ CHANGELOG 規約

- バージョン番号は [セマンティックバージョニング (SemVer)](https://semver.org/) を採用し、各フェーズ完了ごとに `Cargo.toml`、`README.md`、`README_JA.md` のバッジおよびステータス記述を引き上げる。
- `docs/ja/CHANGELOG.md` および `docs/en/CHANGELOG.md` の2ファイルに同一内容の更新履歴（追加・変更・修正）を日本語および英語で正確に追記する。
- Gitタグは注釈付きタグ（Annotated Tag: `git tag -a vX.Y.Z -m "..."`）として作成する。
