# Re:CraftLaunch: コントリビューション規約 (CONTRIBUTING)

`Re:CraftLaunch` への関心および貢献をご検討いただき、誠にありがとうございます！
本プロジェクトは、CraftLaunch 2の原点思想（超軽量・爆速・キーボード特化）を守りながら、高品質かつ持続可能なコードベースを維持することを最優先としています。

---

## 1. 開発指針 & スコープポリシー

- **ミニマリズムの維持**:
  - 新機能の提案は大歓迎ですが、CraftLaunch 3のように「過剰に多機能化し設定が複雑化する」ことは本プロジェクトの最も回避すべき事象です。
  - 「PC全域のインデックス検索」や「重厚なWeb技術の導入」、「複雑な外部スクリプト機構」の追加提案は、原則として採択いたしません。
- **クリーンルーム開発**:
  - 本家の内部コードやプロプライエタリな実装を引き写すことは行わず、外観と操作感のみをRustで自前実装します。

---

## 2. コミットメッセージ規約

コミットメッセージは以下の形式に従ってください：

```text
<prefix>: <日本語による明確な変更要約>

[必要に応じて詳細な説明（日本語）]
```

### プレフィックス一覧
- `feat:` 新機能・新モジュールの追加
- `fix:` バグ修正
- `docs:` ドキュメントのみの変更
- `refactor:` リファクタリング（機能変更なし）
- `test:` テストコードの追加・修正
- `chore:` ビルド構成、依存関係、雑務

---

## 3. プルリクエスト（PR）提出前チェックリスト

PRを提出する前に、ローカル環境で以下のチェックをすべてパスさせてください：

- [ ] `cargo check --all-targets` がエラー・警告ゼロで通過すること。
- [ ] `cargo test --all-targets` および `cargo test --doc` が全件合格すること。
- [ ] `cargo clippy --all-targets -- -D warnings` で警告が 0 件であること。
- [ ] `cargo fmt --check` でコードフォーマットが完全準拠していること。
- [ ] 新規公開APIには自然な日本語のRustdoc（`# Examples`, `# Panics` 等）が付与されていること。
- [ ] Markdownテーブルのパイプ `|` とハイフン `-` が垂直整列されていること。
- [ ] ユーザー固有の生パス（`C:\Users\...`）が含まれず、環境変数（`%USERPROFILE%`）化されていること。
